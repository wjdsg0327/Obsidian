Tauri 入门教程：用熟悉的 Web 技术做小而快的原生应用

这份教程面向已经会一点前端、想把网页能力变成桌面/移动应用的人。你可以把 Tauri 理解为：界面用 HTML/CSS/JS 或任意前端框架写，系统能力和后端逻辑用 Rust 写，中间通过安全的 IPC 通信连接。

Tauri 2.x桌面：Windows / macOS / Linux移动：Android / iOS适合工具类、效率类、跨平台客户端

Tauri 是什么

Tauri 是一个跨平台应用工具包。它不把 Chromium 这种完整浏览器引擎打包进应用，而是使用操作系统自带的 WebView：Windows 用 Edge WebView2，macOS 用 WKWebView，Linux 用 WebKitGTK。这样应用体积通常比 Electron 小很多，同时核心逻辑可以用 Rust 获得更好的性能和安全边界。

核心模型

一个 Tauri 应用通常由两部分组成：前端 WebView 和 Rust Core。前端负责界面、交互、状态展示；Rust Core 负责窗口、文件、系统托盘、通知、数据库、命令、权限和真正敏感的系统操作。

Tauri 的两层结构

适合什么场景

  • 桌面工具：剪贴板、文件处理、开发者工具、启动器、笔记工具。
  • 跨平台客户端：一套 Web UI，多平台打包。
  • 已有 Web 项目转桌面应用：在现有前端外面套一层原生能力。
  • 需要轻量分发：不想每个应用都带一个完整浏览器。
易错点提醒
不要把 Tauri 当成“网页直接拥有系统权限”。Tauri 的安全设计是：前端默认没有随便操作系统的能力，需要 Rust 命令、插件权限和 capability 明确授权。

理解了“前端负责界面、Rust 负责系统能力”之后，下一步就是把开发环境搭好。

环境准备

开发 Tauri 需要两类依赖：Rust 工具链，以及对应平台的系统构建依赖。如果你用 JavaScript/TypeScript 前端，还需要 Node.js 和包管理器。

必装组件

Rust

安装 rustup，使用 stable 工具链。Rust 编译 Tauri Core 和打包应用。

Node.js

如果使用 React/Vue/Svelte/Vite 等前端框架，需要 Node.js。建议配合 pnpm 或 npm。

Windows

需要 Microsoft C++ Build Tools；Windows 10 1803 之后通常已有 WebView2。

Linux / macOS

Linux 需要 WebKitGTK 等开发库；macOS 需要 Xcode 或 Command Line Tools。

环境依赖关系

推荐检查命令

rustc --version
cargo --version
node -v
npm -v
# 如果用 pnpm
corepack enable
pnpm -v
易错点提醒
第一次运行 tauri dev 会编译 Rust 依赖，几分钟很正常。后续因为依赖有缓存，会快很多。

环境准备好后，就可以用官方脚手架创建第一个项目。

创建第一个项目

官方推荐用 create-tauri-app 快速生成项目。它会让你选择项目名、应用标识、前端语言、包管理器和 UI 模板。

推荐新手选择

如果只是入门，建议先选：TypeScript / JavaScript → pnpm 或 npm → Vanilla 或 React。Vanilla 更少干扰，React 更接近真实项目。

# npm 方式
npm create tauri-app@latest
cd tauri-app
npm install
npm run tauri dev

# pnpm 方式
pnpm create tauri-app
cd tauri-app
pnpm install
pnpm tauri dev
创建项目流程

给已有前端项目加 Tauri

如果你已经有 Vite/React/Vue 项目，可以安装 CLI 后运行初始化命令：

npm install -D @tauri-apps/cli@latest
npx tauri init
npx tauri dev
易错点提醒
已有 Vite 项目里，建议把 src-tauri 加到 Vite 的 watch ignore，避免前端开发服务器监听 Rust 编译产物导致额外刷新。

项目跑起来后，最重要的是看懂目录结构，否则很容易不知道代码该写在哪里。

项目结构

典型 Tauri 项目顶层是前端工程，src-tauri/ 里面是 Rust 工程。构建时，前端先打包成静态资源，然后 Rust 工程把这些资源和原生能力一起打包成应用。

tauri-app/
├── package.json          # 前端依赖和脚本
├── index.html
├── src/                  # 前端源码
└── src-tauri/
    ├── Cargo.toml        # Rust 依赖和包信息
    ├── Cargo.lock        # Rust 锁定文件，建议提交
    ├── build.rs          # Tauri 构建脚本
    ├── tauri.conf.json   # Tauri 配置
    ├── capabilities/     # 窗口/权限能力配置
    ├── icons/            # 应用图标
    └── src/
        ├── lib.rs        # Tauri app 核心入口
        └── main.rs       # 桌面入口
构建时资源进入 Rust 应用

几个最常改的文件

  • src/：页面、组件、样式、前端状态。
  • src-tauri/src/lib.rs：注册命令、插件、状态管理。
  • src-tauri/tauri.conf.json：应用名、窗口、构建路径、打包配置。
  • src-tauri/capabilities/default.json：给窗口声明可以使用哪些权限。
易错点提醒
src-tauri/target 是 Rust 编译产物，不要提交；src-tauri/Cargo.lock 建议提交，保证多台机器构建依赖一致。

目录清楚之后，就可以写第一个“前端调用 Rust”的功能了。

前端调用 Rust

Tauri 的核心通信方式是 IPC。最常用的是 Command：在 Rust 里定义函数，用 #[tauri::command] 标记；在前端用 invoke 调用。

Rust 侧定义命令

// src-tauri/src/lib.rs
#[tauri::command]
fn greet(name: String) -> String {
    format!("你好，{}！来自 Rust", name)
}

#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    tauri::Builder::default()
        .invoke_handler(tauri::generate_handler![greet])
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}

前端调用命令

// src/main.ts
import { invoke } from '@tauri-apps/api/core';

const message = await invoke<string>('greet', { name: '老王' });
console.log(message);
Command 的请求-响应过程

错误、异步和事件

  • 命令可以返回 Result<T, E>，前端用 try/catch 接错误。
  • 耗时操作建议写成 async fn，避免阻塞 UI。
  • 事件系统适合“通知状态变化”，例如下载进度、同步完成；但事件不是类型安全的，也没有返回值。
易错点提醒
前端传参对象使用 camelCase，例如 Rust 参数 invoke_message，前端一般写 { invokeMessage: 'Hello' }。返回值和错误都要能被 serde 序列化。

会写 command 之后，你已经能完成大多数“前端界面 + 本地能力”的功能。下一步要补上 Tauri 很重要的一层：权限。

配置、权限与插件

Tauri 2.x 很强调最小权限。即使安装了插件，也通常还要在 capability 里给窗口授权。你可以把它理解成：插件提供能力，permission 描述能力，capability 把能力分配给某个窗口。

常见配置文件

  • tauri.conf.json：配置构建命令、前端 devUrl、窗口标题、打包图标、插件配置。
  • Cargo.toml：Rust 依赖，比如 tauri、插件 crate、serde。
  • package.json：前端依赖和脚本，比如 @tauri-apps/api、@tauri-apps/cli。
  • capabilities/default.json：声明默认窗口允许使用哪些权限。
插件权限模型

常用官方插件

fs

文件系统读写。一定要配置 scope，不要把整个磁盘随便开放。

dialog

打开文件选择、保存对话框、消息框。

shell

启动外部命令。风险高，必须谨慎限定命令和参数。

sql / store

本地数据存储：轻量配置用 store，结构化数据用 SQL。

易错点提醒
开发桌面工具时最容易“为了省事放宽权限”。Tauri 的优势恰恰在于权限边界清楚，建议只开放当前功能需要的目录、命令和插件。

配置和权限做好后，开发体验主要看调试方式和反馈循环。

调试与开发循环

日常开发最常用的是 tauri dev。它会启动前端开发服务器、编译 Rust、打开 WebView 窗口，并监听 src-tauri 的改动。前端如果有热更新，窗口也会像浏览器一样刷新。

开发命令

npm run tauri dev
# 或
pnpm tauri dev
# 或只用 cargo 安装 CLI 时
cargo tauri dev
开发反馈循环

打开 Web Inspector

桌面端可以在 WebView 里右键选择 Inspect，或者用快捷键：Windows/Linux 是 Ctrl + Shift + I，macOS 是 Cmd + Option + I。这能调试前端 DOM、样式、网络请求和 console。

常见问题定位

  • 前端没加载：检查 build.devUrl 和 beforeDevCommand 是否正确。
  • 命令调用失败：检查 invoke_handler 是否注册命令、命令名是否一致、参数是否 camelCase。
  • 插件 API 无权限：检查 capabilities/default.json 是否声明 permission。
  • Linux 编译失败：多数是 WebKitGTK 或系统 dev 包缺失。
易错点提醒
Tauri API 只在 Tauri WebView 环境里可用。把前端单独放浏览器打开时，调用 @tauri-apps/api 可能不可用，这是正常的。

开发调通以后，最后一步是打包成目标平台能安装的应用。

打包发布与学习路线

Tauri 通过 CLI 直接构建和打包应用。桌面端常用 tauri build；移动端使用 tauri android build 或 tauri ios build。不同平台会生成对应格式，例如 Windows 安装包、macOS app/dmg、Linux deb/AppImage/rpm 等。

打包命令

npm run tauri build
# 或
pnpm tauri build
# 或
cargo tauri build
从源码到分发包

建议学习路线

  1. 先跑通 Vanilla 模板：理解窗口、前端、Rust 入口。
  2. 写 3 个命令：返回字符串、读写本地文件、异步请求网络。
  3. 学权限：给文件系统插件配置最小 scope。
  4. 做一个小工具：比如 Markdown 转换器、JSON 格式化器、本地日志查看器。
  5. 学打包：配置图标、应用名、版本、Windows/macOS/Linux 目标。
  6. 再学高级能力：系统托盘、多窗口、自动更新、sidecar、数据库、移动端。

一个入门小项目建议

做一个“本地 Markdown 工具”：左边输入 Markdown，右边预览；用 Rust 命令保存文件；用 dialog 插件选择保存位置；用 store 保存上次打开目录。这个项目能覆盖前端、Rust 命令、插件、权限、配置和打包。

易错点提醒
打包发布不只是 build 成功。macOS、Windows、移动端通常还涉及代码签名、公证、商店要求或证书配置。个人学习阶段可以先本地打包，正式分发再处理签名。

到这里，你已经有了 Tauri 的完整入门地图：先理解架构，再跑项目，再用 command 接通 Rust，最后围绕权限、插件和打包做真实小工具。
