ComfyUI：用节点搭建可复用的生成式 AI 工作流

ComfyUI 不是“输入提示词然后点生成”的单一界面，而是一个节点式推理引擎。它适合需要可控、可复用、可调试流程的人：文本生图、图生图、局部重绘、ControlNet、LoRA、高清修复、视频、批量自动化，都可以拆成节点并保存为工作流。

ComfyUI 是什么

ComfyUI 是开源的节点式生成式 AI 应用和推理引擎。核心价值不是“按钮更多”，而是把一次生成拆成可观察、可连接、可保存的步骤：加载模型、编码提示词、采样、VAE 解码、保存图片，每一步都能替换或扩展。

从黑盒界面到透明工作流

适合谁

  • 想稳定复用生成流程的人，例如固定人物、固定风格、固定尺寸和高清修复链路。
  • 想研究模型组合的人，例如 SDXL、FLUX、LoRA、ControlNet、IPAdapter、放大模型。
  • 想把生图能力接入脚本、服务或自动化流水线的人。
常见误解ComfyUI 初看复杂，不代表它比 WebUI 更难。它只是把隐藏流程全部摊开了。入门时不要从复杂工作流开始，先把“最小生图链路”跑通，再一点点加节点。

安装与运行

优先选择官方 Desktop 或官方推荐方式安装。Windows 用户如果只是使用，可以先用桌面版或便携包；Linux/服务器用户更适合 Git + Python 环境；多项目、多显卡或 Docker 部署时，要把模型目录和数据目录规划好。

安装路线选择

手动安装的基本命令

git clone https://github.com/Comfy-Org/ComfyUI.git
cd ComfyUI
python -m venv venv
# Linux/macOS
source venv/bin/activate
# Windows PowerShell
# .\venv\Scripts\Activate.ps1
pip install -r requirements.txt
python main.py

官方 README 提到，Python 3.13 支持较好，Python 3.12 可作为兼容性回退；PyTorch 建议使用较新的大版本和对应 CUDA。实际选择时，以你的显卡驱动、CUDA、PyTorch 兼容矩阵为准。

建议给老王的安装选择如果是在 24 小时跑 Docker 的小主机上部署，建议用 Docker Compose 或独立 Python 环境，把 `models`、`input`、`output`、`custom_nodes` 映射到持久化目录，方便备份和迁移。

节点工作流心智模型

ComfyUI 的工作流是有方向的数据图。节点左边是输入，右边是输出；连线传递的是有类型的数据，例如 `MODEL`、`CLIP`、`VAE`、`LATENT`、`CONDITIONING`、`IMAGE`。理解这些类型，比死记节点名字重要。

一次生图的核心数据流

三个关键概念

节点

每个节点执行一个动作，例如加载模型、编码文字、采样、解码、保存。

连线

连线不是装饰，它传递类型明确的数据。类型不匹配时连不上或会报错。

工作流

工作流可以保存成 JSON，也常被嵌入到 PNG 元数据里，拖进 ComfyUI 就能恢复。

队列

点击 Queue Prompt 后，ComfyUI 按图执行。改参数后再入队生成新结果。

常见错误把节点当成“插件按钮”乱装。正确方式是先问：我现在缺哪一步？缺的是预处理、模型加载、条件控制、采样、后处理，还是保存输出？

第一张图的最小流程

第一次不要追求复杂。目标是跑通：选 checkpoint、写正向提示词、写反向提示词、设置尺寸和 seed、采样、保存图片。只要这条链路通了，后面的图生图、ControlNet、LoRA 都是在它上面加节点。

最小文生图工作流

推荐第一组参数

  • 模型：先用一个你确定能跑的 SDXL 或 SD1.5 checkpoint。
  • 尺寸：SD1.5 先用 512x512；SDXL 先用 1024x1024 或 832x1216 这类常见尺寸。
  • Steps：20 到 30；CFG：5 到 8；Sampler/Scheduler 先用工作流默认值。
  • Seed：想复现就固定 seed；想探索就随机 seed。
小技巧先保存一个“干净基础工作流”。以后每次做新玩法，都从基础工作流复制一份，不要在唯一文件上越改越乱。

模型文件与目录

ComfyUI 的多数问题不是节点本身，而是模型放错位置、文件格式不对、工作流需要的模型与你下载的不是同一种。记住：下载模型前先看工作流说明和节点说明。

常见模型目录映射

常见目录速查

  • Checkpoint：`.safetensors` 或 `.ckpt`，通常放 `models/checkpoints`。
  • LoRA：`.safetensors`，通常放 `models/loras`。
  • VAE：通常放 `models/vae`。
  • ControlNet：通常放 `models/controlnet`。
  • 放大模型：`.pth` 或 `.safetensors`，通常放 `models/upscale_models`。
  • FLUX、SD3 系列可能涉及 `diffusion_models`、`text_encoders`、`vae` 等分离组件，必须按具体工作流说明放置。
Hugging Face 下载注意一个仓库不一定等于一个 ComfyUI 模型文件。仓库里可能有 Diffusers 目录结构、配置文件、GGUF、LoRA、VAE、workflow JSON。不要看到 `.safetensors` 就随便放，先看 README 或工作流要求。

常用工作流套路

掌握基础链路后，ComfyUI 的学习路线可以按“逐步加控制”推进：先文生图，再图生图，再局部重绘，再 ControlNet，再 LoRA 和 IPAdapter，最后做高清修复、批量和视频。

从简单到复杂的工作流成长路线

文生图

用文字条件生成图片。关注 checkpoint、提示词、尺寸、采样器、步数、CFG、seed。适合探索风格、构图和模型能力。

图生图

输入一张图，把它编码成 latent，再通过 denoise 控制变化幅度。denoise 越低越贴近原图，越高越接近重新生成。

局部重绘

用 mask 指定要改的区域，适合修手、换衣服、改背景、补细节。关键是 mask 边缘、denoise 和提示词要配合。

ControlNet

用边缘、深度、姿态、线稿等结构条件控制画面。它解决的是“我想要这个构图/姿态/轮廓”的问题。

LoRA

LoRA 用来注入人物、画风、服装、物体或特定概念。通常接在 checkpoint 后面，权重不宜盲目拉满，0.6 到 1.0 是常见探索区间。

实践顺序先固定 seed，单次只改一个变量。否则你不知道结果变化来自提示词、模型、采样器、LoRA 权重，还是随机种子。

插件与 Manager

ComfyUI 的生态主要靠 custom nodes 扩展。官方文档推荐优先用 ComfyUI Manager 管理插件；也可以手动把 Git 仓库 clone 到 `custom_nodes`，再安装依赖并重启。

加载别人工作流时的处理流程

Manager 常用功能

  • 安装、禁用、卸载、更新 custom nodes。
  • 打开别人工作流后，安装缺失节点。
  • 下载部分模型，例如 checkpoint、LoRA、ControlNet、VAE。
  • 更新 ComfyUI 和插件，部分版本支持快照与恢复。

手动安装插件的基本方法

cd ComfyUI/custom_nodes
git clone 插件仓库地址
cd 插件目录
pip install -r requirements.txt
# 然后重启 ComfyUI
安全提醒custom node 本质上是 Python 代码，能执行本机操作。不要随便安装来源不明的节点；更新前最好做快照或备份，尤其是生产环境。

性能与显存优化

ComfyUI 的性能瓶颈通常在显存、模型大小、分辨率、采样步数和额外控制节点。显存不够时，不要只盯着换模型，也要看尺寸、batch、VAE、ControlNet、放大流程和是否启用了不必要节点。

影响显存的主要因素

优化顺序

  1. 先降低分辨率或 batch，不要一开始就高清修复。
  2. 减少 ControlNet、IPAdapter、多个 LoRA 叠加带来的额外开销。
  3. 使用适合显存的模型版本，例如 fp16、量化模型或更小基座。
  4. 把高清放大拆成后处理，不要在第一阶段就生成超大图。
  5. 长期部署时固定环境版本，避免今天更新插件、明天工作流不可复现。
判断思路如果是 CUDA out of memory，先看尺寸和 batch；如果是节点 import failed，看 Python 依赖；如果是模型不显示，优先检查目录和文件格式。

API、自动化与部署

ComfyUI 可以通过本地服务接口集成到脚本和业务系统里。常见用法是保存工作流 JSON，把可变参数替换掉，然后通过 API 提交队列，最后读取输出图片。这样可以做批量出图、封装成内部工具，或接入 Web 服务。

自动化调用链路

部署建议

  • 个人使用：本机 `127.0.0.1:8188` 即可，避免无认证暴露到公网。
  • 局域网使用：绑定局域网地址前，确认网络可信，最好加反向代理认证。
  • 服务器使用：使用 Docker 或 systemd 管理进程，持久化 `models`、`custom_nodes`、`input`、`output`。
  • 对外提供服务：不要把原生 ComfyUI 直接裸露公网，应做鉴权、限流、队列隔离和文件清理。
安全边界ComfyUI、插件和模型下载都可能接触本地文件和 Python 环境。公网部署必须按服务端应用对待，而不是当作普通网页。

排错清单

ComfyUI 报错时先看终端日志，再看红色节点和浏览器提示。大多数问题能按“节点、模型、依赖、显存、版本”五类定位。

排错决策树

快速定位

  • 红色节点：安装缺失 custom nodes，重启后看日志。
  • 模型列表没有文件：检查目录、扩展名、是否需要刷新或重启。
  • `CUDA out of memory`：降分辨率、batch、ControlNet 数量、高清放大倍率。
  • `ModuleNotFoundError` 或 `ImportError`：进入对应插件目录安装 `requirements.txt`，或检查 Python 版本。
  • 工作流能跑但图很差：先固定 seed，再逐项调整提示词、CFG、steps、采样器、LoRA 权重。
  • 更新后坏了：用 Manager 快照恢复，或回退 custom node Git 版本。
建议保留的目录结构把常用工作流单独建文件夹，例如 `workflows/basic`、`workflows/controlnet`、`workflows/loras`、`workflows/upscale`。每个工作流旁边放一个说明 Markdown，记录需要的模型和插件。
