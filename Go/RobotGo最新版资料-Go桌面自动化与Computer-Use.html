RobotGo 最新版资料：Go 桌面自动化与 AI Computer Use

RobotGo 是 Go 生态里的跨平台桌面自动化库：能控制鼠标、键盘，读取屏幕，处理截图/位图，管理窗口与进程，也常被用来做自动测试、RPA、小型桌面机器人、AI Computer Use 执行层。

仓库：go-vgo/robotgo最新标签：v2.0.0-beta2master 提交：766c6abGo module：go 1.25.0

1. 它是什么，适合做什么

RobotGo 的定位可以理解成“Go 版桌面遥控器”。你的程序通过它向操作系统发送鼠标/键盘事件，读取屏幕像素或截图，再根据图像、窗口、进程状态做下一步动作。

RobotGo 在自动化程序中的位置

适合的场景

  • 桌面自动测试：打开应用、点击按钮、输入文本、截图校验。
  • RPA/办公自动化：批量处理 GUI 软件、旧系统、不能直接调 API 的程序。
  • AI Computer Use：让大模型/规则系统根据截图决定下一步操作。
  • 跨平台小工具：在 macOS、Windows、Linux 上做统一的鼠标键盘脚本。
边界提醒
RobotGo 是“控制真实桌面”的库，不是浏览器自动化框架。网页自动化优先 Playwright/Selenium；只有遇到非网页 UI、远程桌面、系统弹窗、图形软件时，RobotGo 才更合适。

3. 安装与平台依赖

最简单的引入方式是 Go module 里直接 import：

import "github.com/go-vgo/robotgo"

// 或更新依赖
go get -u github.com/go-vgo/robotgo
安装依赖按平台分层

macOS

brew install go
xcode-select --install

还要在 系统设置 → 隐私与安全性 给程序/终端添加 辅助功能、屏幕录制/屏幕与系统音频录制 权限，否则键鼠控制和截图会失败。

Windows

winget install Golang.go
winget install MartinStorsjo.LLVM-MinGW.UCRT
# 或
winget install BrechtSanders.WinLibs.POSIX.UCRT

如果用传统 Cgo 后端，需要 GCC 在 PATH 中可用。若使用新版纯 Go win 后端，可减少 MinGW 依赖。

Ubuntu / Debian

# Go 可用 apt/snap/官网下载，README 示例用 snap
sudo snap install go --classic
sudo apt install gcc libc6-dev
sudo apt install libx11-dev xorg-dev libxtst-dev
sudo apt install xsel xclip
sudo apt install libpng++-dev
sudo apt install xcb libxcb-xkb-dev x11-xkb-utils libx11-xcb-dev libxkbcommon-x11-dev libxkbcommon-dev
常见错误
png.h: No such file or directory 通常是 libpng 开发包缺失；Linux 安装 libpng++-dev / libpng-devel，Windows 则要注意所用 GCC 环境是否带有对应库。

4. Cgo-free 与后端选择

新版 RobotGo 的重点变化之一是提供实验性的纯 Go 后端。它们暴露同样的 robotgo API，主要通过 build tag 选择实现，目标是 CGO_ENABLED=0 也能构建，方便交叉编译和部署。

Linux 后端选择：X11、Wayland、libei

后端与构建标签

  • win：Windows 纯 Go 后端，避免 MinGW。
  • mac：macOS 通过 purego 调用 Quartz/CoreGraphics；窗口管理能力有限，部分返回 ErrNotSupported。
  • x11：Linux X11 纯 Go X 协议。
  • wayland：Linux wlroots Wayland，适合 Sway/Hyprland/Wayfire；GNOME/KDE 不原生支持所需协议。
  • libei：Linux GNOME/KDE 通过 xdg-desktop-portal RemoteDesktop 处理鼠标键盘；屏幕捕获和窗口管理不支持。
  • purego：跨平台快捷标签，macOS 选 mac，Windows 选 win，Linux 默认选 wayland；Linux 可组合 purego,x11 或 purego,libei。
# 跨平台纯 Go 默认后端
go build -tags purego .

# Linux X11 纯 Go
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -tags "purego,x11" .

# Windows 纯 Go
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -tags win .

# macOS 纯 Go
CGO_ENABLED=0 GOOS=darwin GOARCH=arm64 go build -tags mac .

# Wayland wlroots
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -tags wayland .

# GNOME/KDE portal/libei
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -tags libei .
别默认 Wayland 万能：README 明确说 Wayland 后端需要 wlroots 协议，GNOME/KDE 不原生支持；GNOME/KDE 应评估 libei，但它只做鼠标键盘，不做截图/窗口管理。

5. 鼠标与键盘自动化

鼠标键盘是 RobotGo 最核心、最稳定的用法。基本思路：移动到坐标 → 点击/拖拽/滚动 → 输入文本或快捷键。

鼠标常用 API

Move、MoveRelative、MoveSmooth、DragSmooth、Click、Toggle、Scroll、ScrollDir、Location

键盘常用 API

Type、TypeStr、KeyTap、KeyToggle、KeyDown、KeyUp、Paste、WriteAll、ReadAll

一次典型 GUI 操作流
package main

import (
    "fmt"
    "github.com/go-vgo/robotgo"
)

func main() {
    robotgo.MouseSleep = 100
    robotgo.Move(100, 200)
    robotgo.MoveRelative(10, -20)
    robotgo.MoveSmooth(300, 300, 1.0, 80.0)

    robotgo.Click("left")          // 左键单击
    robotgo.Click("left", true)    // 左键双击
    robotgo.ScrollDir(5, "up")

    x, y := robotgo.Location()
    fmt.Println("mouse:", x, y)
}
package main

import "github.com/go-vgo/robotgo"

func main() {
    robotgo.KeySleep = 100
    robotgo.Type("Hello RobotGo")
    robotgo.KeyTap("enter")
    robotgo.KeyTap("a", "ctrl")       // Ctrl+A / macOS 按需用 cmd
    robotgo.KeyTap("v", robotgo.CmdCtrl())

    _ = robotgo.Paste("用剪贴板粘贴中文通常比逐字输入更稳")
}
中文输入建议
真实桌面输入法状态不可控时，逐字符 Type 可能不稳。自动化中文文本更推荐 Paste：写入剪贴板，再触发 Ctrl/Cmd+V。

6. 屏幕、截图、图像与 OCR

RobotGo 可以获取屏幕尺寸、缩放尺寸、像素颜色、截图，并把位图转换成 Go 标准 image.Image。这部分是“看见屏幕”的基础。

从屏幕到判断条件
package main

import (
    "fmt"
    "github.com/go-vgo/robotgo"
)

func main() {
    w, h := robotgo.GetScreenSize()
    fmt.Println("screen:", w, h)

    color := robotgo.GetPixelColor(100, 200)
    fmt.Println("pixel:", color)

    img, err := robotgo.CaptureImg(10, 20, 300, 200)
    if err != nil { panic(err) }
    _ = robotgo.Save(img, "capture.png")
}

位图与图片转换

  • CaptureScreen 返回 CBitmap，用完要 defer robotgo.FreeBitmap(bit)。
  • CaptureImg / CaptureGo 更接近 Go 标准图像处理流程。
  • Save、SavePng、SaveJpeg 可保存图片。
  • ToImage、ToRGBA、ImgToBitmap、ToByteImg 等做格式转换。
  • GetText(imgPath, lang) 通过 Tesseract OCR 读取图片文字，需要额外 OCR 环境。
多屏与缩放
高 DPI、系统缩放、多显示器会影响坐标。RobotGo 提供 DisplaysNum、GetDisplayBounds、GetScreenRect、GetScaleSize、SysScale、Scale 等能力。写脚本时建议先打印坐标和尺寸，再做点击。

7. 窗口与进程控制

窗口和进程能力让脚本不再完全依赖固定坐标：可以按进程名查 PID、激活窗口、读标题、最小化/最大化/关闭窗口。

窗口自动化：先找到目标，再操作目标
package main

import (
    "fmt"
    "github.com/go-vgo/robotgo"
)

func main() {
    pids, err := robotgo.FindIds("chrome")
    if err != nil || len(pids) == 0 {
        fmt.Println("not found")
        return
    }

    pid := pids[0]
    _ = robotgo.ActivePid(pid)
    fmt.Println("title:", robotgo.GetTitle(pid))

    robotgo.KeyTap("l", robotgo.CmdCtrl())
    _ = robotgo.Paste("https://github.com/go-vgo/robotgo")
    robotgo.KeyTap("enter")
}

常用能力

  • 进程：Pids、PidExists、FindName、FindNames、FindIds、FindPath、Process、Run、Kill。
  • 窗口：GetActive、SetActive、GetHandle、GetTitle、ActiveName、ActivePid、MinWindow、MaxWindow、CloseWindow。
谨慎使用 Kill / CloseWindow：自动化脚本里最好先打印目标 PID、标题、路径，确认命中目标后再关闭或杀进程，避免误伤正在编辑的窗口。

8. 实战模式与工程建议

RobotGo 项目不要写成“一串坐标点击”。稳定的桌面自动化一般要做到：定位目标、等待状态、动作节流、失败可恢复。

可靠自动化闭环

推荐工程结构

my-robot/
  main.go              # 入口，只编排任务
  action/              # 点击、输入、滚动、快捷键封装
  vision/              # 截图、颜色、OCR、模板匹配
  app/                 # 具体应用流程，如 chrome.go / excel.go
  config/              # 坐标、等待时间、目标窗口名
  logs/                # 截图和执行日志

写脚本的几个原则

  • 先激活窗口，再点击坐标，减少焦点错误。
  • 点击前后截图或读像素，确认 UI 处于预期状态。
  • 所有动作加短延迟：MouseSleep、KeySleep、MilliSleep。
  • 坐标配置化，不要散落在代码里。
  • 把“危险操作”做二次确认，比如删除、提交、付款、关闭未保存窗口。
  • 在 Linux 桌面里先确定自己是 X11、wlroots Wayland、还是 GNOME/KDE Wayland，再选后端。

9. 常见坑与排错

1. 编译失败

检查 Go、GCC、X11/PNG/XCB/XKB 依赖。Windows 检查 MinGW/llvm-mingw PATH。想避开 Cgo，可评估纯 Go build tags。

2. macOS 无法点击/截图

通常是权限没给：终端或最终 app 需要辅助功能、屏幕录制权限。改权限后重启 app/终端。

3. Linux Wayland 不工作

wlroots Wayland 后端依赖特定协议；GNOME/KDE 不原生支持。GNOME/KDE 看 libei，但 libei 只支持鼠标键盘。

4. 坐标偏移

高 DPI、缩放、多屏导致。打印 GetScreenSize、GetScaleSize、GetDisplayBounds，必要时启用/处理 Scale。

5. 中文输入错乱

优先用 Paste 而不是逐字 Type；同时确认剪贴板程序 xsel/xclip 可用。

6. 官方 API 文档不一致

仓库说明 docs/doc.md 已弃用，不再更新。以 pkg.go.dev、README、examples、源码为准。

最小诊断程序
新环境先跑一个只打印版本、屏幕尺寸、鼠标坐标、像素颜色的小程序；这些成功后，再测试点击和输入。
package main

import (
    "fmt"
    "github.com/go-vgo/robotgo"
)

func main() {
    fmt.Println("version:", robotgo.GetVersion())
    fmt.Println("screen:", robotgo.GetScreenSize())
    fmt.Println("scale:", robotgo.GetScaleSize())
    fmt.Println("mouse:", robotgo.Location())
    fmt.Println("pixel:", robotgo.GetPixelColor(10, 10))
}
