go-ole：Go 调用 Windows COM/OLE 的实用手册

github.com/go-ole/go-ole 是 Go 生态里常用的 Windows COM 绑定库，不依赖 cgo，而是通过 Windows 共享库/系统调用访问 COM。它适合自动化 Excel、Outlook、IE、Windows Media Player、MSXML、WMI、第三方 COM Server，以及处理 IDispatch、VARIANT、SafeArray、连接点事件和部分 WinRT 场景。

1. 项目定位

go-ole 解决的是“Go 程序如何和 Windows COM 对象说话”。COM 对象通常由 Windows、Office、浏览器控件、企业软件或 .NET/VC++ 组件提供，Go 程序通过 ProgID/CLSID 创建对象，再用 IDispatch 读取属性、设置属性、调用方法。

适合：Windows 桌面/Office 自动化、企业 COM SDK、WMI/系统管理、COM 事件回调、旧系统集成。
不适合：跨平台业务逻辑、现代 Web API 调用、浏览器 DOM 自动化。非 Windows 平台可编译，但 COM 调用基本是 NOOP/不可用。

2. COM/OLE 基础模型

COM 的核心概念有四个：CLSID/ProgID 用来找到类，IUnknown 管生命周期和接口查询，IDispatch 提供动态调用，VARIANT 承载跨语言参数和返回值。

ProgID / CLSID

Excel.Application 是 ProgID；{000...} 形式是 CLSID/IID。go-ole 可互相转换。

IUnknown

COM 根接口，提供 QueryInterface、AddRef、Release。

IDispatch

自动化接口，先把方法/属性名转 DISPID，再 Invoke。

VARIANT / SafeArray

统一包装 string、int、bool、BSTR、IDispatch、数组等 COM 类型。

3. 安装、平台与线程

go get github.com/go-ole/go-ole

README 明确：库可以在 Go 支持的平台上构建；但 COM API 是 Windows 专属，非 Windows 主要用于保证 go get/交叉构建不炸，运行时调用没有真实 COM 能力。

线程规则非常重要

COM 初始化是“线程相关”的。每个调用了 CoInitialize/CoInitializeEx 的 OS 线程，都必须在同一线程调用 CoUninitialize。Go goroutine 会迁移 OS 线程，所以复杂自动化建议锁线程。

runtime.LockOSThread()
defer runtime.UnlockOSThread()

if err := ole.CoInitializeEx(0, ole.COINIT_APARTMENTTHREADED); err != nil {
    panic(err)
}
defer ole.CoUninitialize()
STA/MTA：Office 自动化通常用 COINIT_APARTMENTTHREADED。并发 COM 调用不要随便多 goroutine 共享同一个 COM 对象，必要时用专门的 COM worker goroutine。

4. 标准调用流程

最常见流程：初始化 COM → 创建/获取对象 → QueryInterface 到 IDispatch → 调属性/方法 → Release → CoUninitialize。

package main

import (
    "runtime"
    ole "github.com/go-ole/go-ole"
    "github.com/go-ole/go-ole/oleutil"
)

func main() {
    runtime.LockOSThread()
    defer runtime.UnlockOSThread()

    ole.CoInitialize(0)
    defer ole.CoUninitialize()

    unknown, err := oleutil.CreateObject("Excel.Application")
    if err != nil { panic(err) }
    defer unknown.Release()

    excel, err := unknown.QueryInterface(ole.IID_IDispatch)
    if err != nil { panic(err) }
    defer excel.Release()

    oleutil.MustPutProperty(excel, "Visible", true)
    workbooks := oleutil.MustGetProperty(excel, "Workbooks").ToIDispatch()
    defer workbooks.Release()
    workbook := oleutil.MustCallMethod(workbooks, "Add").ToIDispatch()
    defer workbook.Release()
}

5. oleutil 高层 API

oleutil 是日常最推荐入口，封装了 ProgID 创建、属性读写、方法调用、枚举遍历等常用模式。

API用途
ClassIDFrom(programID)ProgID 或 CLSID 字符串转 GUID。
CreateObject(programID)创建 COM 对象，返回 IUnknown。
GetActiveObject(programID)获取已运行对象，例如已打开的 Excel。
CallMethod / MustCallMethod调用方法；Must 版本遇错 panic，适合示例，不适合生产主流程。
GetProperty / MustGetProperty读取属性或索引属性，如 Worksheets, 1。
PutProperty / PutPropertyRef设置属性或引用属性。
ForEach通过 _NewEnum/IEnumVARIANT 遍历集合。
ConnectObject连接 COM 事件源和 Go 实现的 sink。
unknown, _ := oleutil.CreateObject("Excel.Application")
excel, _ := unknown.QueryInterface(ole.IID_IDispatch)
oleutil.PutProperty(excel, "Visible", true)

workbooks := oleutil.MustGetProperty(excel, "Workbooks").ToIDispatch()
workbook := oleutil.MustCallMethod(workbooks, "Add").ToIDispatch()
worksheet := oleutil.MustGetProperty(workbook, "Worksheets", 1).ToIDispatch()
cell := oleutil.MustGetProperty(worksheet, "Cells", 1, 1).ToIDispatch()
oleutil.PutProperty(cell, "Value", "Hello from Go")

6. IDispatch 与动态调用

IDispatch 是 OLE Automation 的核心。go-ole 支持两种层级：直接用 IDispatch 方法，或者通过 oleutil 包装。

  • GetIDsOfName：把方法/属性名转成 DISPID。
  • Invoke：传 DISPID、调用类型和 VARIANT 参数数组。
  • CallMethod：等价于 Invoke(..., DISPATCH_METHOD)。
  • GetProperty：等价于 Invoke(..., DISPATCH_PROPERTYGET)。
  • PutProperty：等价于 Invoke(..., DISPATCH_PROPERTYPUT)。
COM 参数顺序底层通常是反向压栈；go-ole 的 invoke 已处理这一点，正常按自然顺序传 Go 参数即可。
ids, err := excel.GetIDsOfName([]string{"Visible"})
if err != nil { panic(err) }
_, err = excel.Invoke(ids[0], ole.DISPATCH_PROPERTYPUT, true)

7. VARIANT 类型系统

VARIANT 是 COM 里的“动态类型盒子”。go-ole 用 VT 枚举记录类型，用 Val 保存值/指针。日常使用尽量通过 Value()、ToString()、ToIDispatch()、ToArray() 转成 Go 类型。

VT含义常见 Go 映射
VT_EMPTY / VT_NULL空值/nullole.EMPTY、ole.NULL、nil
VT_I1/I2/I4/I8有符号整数int8/int16/int32/int64/int
VT_UI1/UI2/UI4/UI8无符号整数uint8/uint16/uint32/uint64/uint
VT_R4/R8浮点float32/float64
VT_BOOLCOM booltrue 通常为 0xffff
VT_BSTRCOM 字符串string
VT_DISPATCHIDispatch 指针*ole.IDispatch
VT_ARRAY|...SafeArray[]byte、[]string、ToArray()
VT_BYREF引用参数*int32、*string、*VARIANT 等
v := oleutil.MustGetProperty(cell, "Value")
defer v.Clear()

fmt.Println(v.Value())
fmt.Println(v.ToString())

obj := oleutil.MustGetProperty(excel, "Workbooks").ToIDispatch()
defer obj.Release()

8. SafeArray 数组

很多 COM 方法返回集合或二进制数据时会用 SafeArray。go-ole 公开了 SafeArray、SafeArrayBound、SafeArrayConversion，常用转换有：

  • VARIANT.ToArray()：把 VARIANT 转成 SafeArrayConversion。
  • ToStringArray()：转字符串数组。
  • ToByteArray()：转字节数组。
  • ToValueArray()：按 VARIANT 元素转 []interface{}。
  • GetType()、GetDimensions()、GetSize()、TotalElements()：读取数组元信息。
  • Release()：释放 SafeArray 内存。
variant := oleutil.MustCallMethod(winsock, "GetData")
arr := variant.ToArray()
defer arr.Release()
bytes := arr.ToByteArray()

9. IUnknown / GUID / 错误

GUID

NewGUID 支持多种字符串形式，并格式化为 {XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX}。常用预定义 IID 包括 IID_IUnknown、IID_IDispatch、IID_IEnumVariant、IID_IConnectionPointContainer、IID_IConnectionPoint、IID_IInspectable、IID_IProvideClassInfo。

IUnknown 生命周期

COM 使用引用计数。每次拿到新的 COM 接口指针，通常都要在不用时 Release()。go-ole 不会替你自动管理所有 COM 对象生命周期。

OleError

OleError 包装 HRESULT，提供 Code()、Description()、SubError()、Unwrap()。IDispatch 调用失败时，可能带 EXCEPINFO 子错误描述。

10. 事件连接点

COM 事件通常通过 Connection Point 机制实现。go-ole 提供 IConnectionPointContainer、IConnectionPoint 与 oleutil.ConnectObject。你需要在 Go 里构造一个满足 COM vtable 形状的事件接收对象，并实现 QueryInterface、AddRef、Release、Invoke 等回调。

事件回调属于高级用法，涉及 unsafe、syscall.NewCallback、引用计数和消息循环。生产代码要非常小心生命周期。
// 伪代码：核心结构
iid, _ := ole.CLSIDFromString("{事件接口IID}")
sink := (*ole.IUnknown)(unsafe.Pointer(myReceiver))
cookie, err := oleutil.ConnectObject(sourceDispatch, iid, sink)
_ = cookie
_ = err

var msg ole.Msg
for running {
    ole.GetMessage(&msg, 0, 0, 0)
    ole.DispatchMessage(&msg)
}

11. WinRT 支持

仓库还包含部分 WinRT 辅助函数：RoInitialize、RoUninitialize、RoActivateInstance、RoGetActivationFactory、HString、NewHString、DeleteHString。这部分面向 Windows Runtime，不是传统 OLE Automation 的日常入口。

if err := ole.RoInitialize(1); err != nil {
    panic(err)
}
defer ole.RoUninitialize()

h, _ := ole.NewHString("Windows.Foundation.Uri")
fmt.Println(h.String())
ole.DeleteHString(h)

12. 典型示例

Excel 写入单元格并退出

ole.CoInitialize(0)
defer ole.CoUninitialize()

unknown, err := oleutil.CreateObject("Excel.Application")
if err != nil { panic(err) }
defer unknown.Release()

excel, err := unknown.QueryInterface(ole.IID_IDispatch)
if err != nil { panic(err) }
defer excel.Release()

oleutil.PutProperty(excel, "Visible", true)
workbooks := oleutil.MustGetProperty(excel, "Workbooks").ToIDispatch()
defer workbooks.Release()
workbook := oleutil.MustCallMethod(workbooks, "Add", nil).ToIDispatch()
defer workbook.Release()
worksheet := oleutil.MustGetProperty(workbook, "Worksheets", 1).ToIDispatch()
defer worksheet.Release()
cell := oleutil.MustGetProperty(worksheet, "Cells", 1, 1).ToIDispatch()
defer cell.Release()
oleutil.PutProperty(cell, "Value", 12345)

oleutil.PutProperty(workbook, "Saved", true)
oleutil.CallMethod(workbook, "Close", false)
oleutil.CallMethod(excel, "Quit")

获取已打开的 Excel

unknown, err := oleutil.GetActiveObject("Excel.Application")
if err != nil {
    // 没有运行中的 Excel，或对象没有注册到 ROT
    panic(err)
}
defer unknown.Release()
excel := unknown.MustQueryInterface(ole.IID_IDispatch)
defer excel.Release()
fmt.Println(oleutil.MustGetProperty(excel, "Version").ToString())

Outlook 联系人遍历

unknown, _ := oleutil.CreateObject("Outlook.Application")
outlook, _ := unknown.QueryInterface(ole.IID_IDispatch)
ns := oleutil.MustCallMethod(outlook, "GetNamespace", "MAPI").ToIDispatch()
folder := oleutil.MustCallMethod(ns, "GetDefaultFolder", 10).ToIDispatch()
contacts := oleutil.MustCallMethod(folder, "Items").ToIDispatch()
count := int(oleutil.MustGetProperty(contacts, "Count").Value().(int32))
for i := 1; i <= count; i++ {
    item, err := oleutil.GetProperty(contacts, "Item", i)
    if err == nil && item.VT == ole.VT_DISPATCH {
        name := oleutil.MustGetProperty(item.ToIDispatch(), "FullName")
        fmt.Println(name.Value())
    }
}

13. 常见坑与最佳实践

线程初始化不匹配

每个 CoInitialize 必须对应同线程 CoUninitialize。建议 runtime.LockOSThread。

忘记 Release

IUnknown、IDispatch、集合、单元格等接口对象用完释放；否则 Excel 等进程容易残留。

Must 系列滥用

示例里方便，但生产代码最好用返回 error 的版本，并记录 ProgID、属性名、参数。

32/64 位不匹配

COM Server、Office、Go 程序架构不一致时可能创建失败。检查 Office 位数和 COM 注册表。

Office 弹窗阻塞

保存/关闭前设置 DisplayAlerts=false 或 Saved=true，否则后台自动化会卡住。

VARIANT 类型断言错误

Value() 支持类型有限，复杂对象先看 VT，再 ToIDispatch/ToArray/ToString。

推荐封装：把 Excel/Outlook/WMI 等业务对象再包一层 Go 结构体，统一处理 Release、错误、类型转换和日志，不要在业务代码里散落大量 oleutil.Must...。
