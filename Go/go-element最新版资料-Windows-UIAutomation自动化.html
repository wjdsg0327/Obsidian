go-element：Go 操作 Windows UI Automation 的高性能封装

github.com/auuunya/go-element 是一个面向 Windows 窗体自动化的 Go 库，直接封装 Microsoft UI Automation COM 接口。它适合做桌面应用 UI 树探测、控件查找、按钮点击、文本写入、计算器/记事本/资源管理器自动化，以及为 AI Computer Use/桌面 RPA 工具提供 Windows UIA 层能力。

1. 项目定位

Windows UI Automation（UIA）是微软提供的桌面 UI 可访问性与自动化框架。相比纯坐标点击，UIA 可以按窗口句柄、元素名称、AutomationId、ControlType、Pattern 等方式定位控件，因此更稳定、更适合自动化真实桌面应用。

适合场景

  • 自动化 Windows 原生应用、Win32、WPF、UWP、部分 Electron/Chromium 窗口。
  • 读取 UI 树，导出 JSON，做 Computer Use 感知层。
  • 调用 Invoke/Value/Toggle/SelectionItem 等 Pattern。
  • 需要比鼠标坐标更稳定的 RPA。

不适合场景

  • 跨平台桌面自动化：本库本质上是 Windows UIA。
  • 网页 DOM 自动化：优先 Playwright/Selenium。
  • 只需要键鼠模拟：RobotGo 更直接。
  • 复杂事件订阅：源码已有接口但 README 任务列表仍标注事件监听待完善。
核心改进：README 标明项目重点是 Cache Request 批量获取属性/Pattern、零反射、显式 Release 管理 COM 生命周期，以及 Element.FindByName/FindByAutomationId 这类便捷查询。

3. 架构与调用流程

  1. CoInitialize() 初始化 COM。
  2. GetWindowForString(class, title) 找到目标窗口句柄。
  3. CreateInstance(CLSID_CUIAutomation, IID_IUIAutomation, CLSCTX_ALL) 创建 UIAutomation 客户端。
  4. ElementFromHandle 从 HWND 得到 UIA 根元素。
  5. TraverseUIElementTree 遍历并缓存 UI 树。
  6. 用 FindByName/FindByAutomationId 或自定义搜索定位元素。
  7. 调用 GetValuePattern/GetInvokePattern 等执行交互。
  8. 所有 COM 对象用完 Release()。

4. 快速开始

打印窗口 UI 树

package main

import uia "github.com/auuunya/go-element"

func main() {
    if err := uia.CoInitialize(); err != nil { panic(err) }
    defer uia.CoUninitialize()

    hwnd, _ := uia.GetWindowForString("Chrome_WidgetWin_1", "")
    instance, _ := uia.CreateInstance(uia.CLSID_CUIAutomation, uia.IID_IUIAutomation, uia.CLSCTX_INPROC_SERVER)
    ppv := uia.NewIUIAutomation(uia.NewIUnKnown(instance))
    defer ppv.Release()

    root, _ := uia.ElementFromHandle(ppv, hwnd)
    defer root.Release()

    tree := uia.TraverseUIElementTree(ppv, root)
    uia.TreeString(tree, 0)
}

记事本写入文本

hwnd, _ := uia.GetWindowForString("Notepad", "")
instance, _ := uia.CreateInstance(uia.CLSID_CUIAutomation, uia.IID_IUIAutomation, uia.CLSCTX_ALL)

5. Element 高层封装

Element 是库里最适合业务层直接使用的结构体：它把 IUIAutomationElement 的 Current/Cached 属性填充到 Go 字段中，并提供搜索与 Pattern 获取方法。

能力说明
属性填充Populate(cached bool) 调用一组属性读取方法，填入 CurrentName、CurrentClassName、CurrentAutomationId 等字段。
树结构Element 有 Children，可用于 JSON 序列化 UI 树。
快捷查找FindByName、FindByAutomationId。
PatternGetValuePattern、GetInvokePattern、GetTogglePattern、GetExpandCollapsePattern、GetSelectionItemPattern。
业务代码建议优先走 Element 层；只有需要高级 UIA 条件、缓存、事件时再下沉到 IUIAutomation* 原始接口。

6. 查找与遍历

go-element 提供了两条路线：一是构建完整 UI 树后在内存里搜索；二是用 UIA 原生 FindFirst/FindAll 和条件查询。

内存树搜索

tree := uia.TraverseUIElementTree(ppv, root)
btn := tree.FindByAutomationId("num1Button")
edit := tree.FindByName("文本编辑器")

allButtons := uia.FindElems(tree, func(e *uia.Element) bool {
    return e.CurrentControlType == uia.UIA_ButtonControlTypeId
})

原生条件搜索

variant, _ := uia.VariantFromString("num1Button")
cond, _ := ppv.CreatePropertyCondition(uia.UIA_AutomationIdPropertyId, variant)
btn, _ := root.FindFirst(uia.TreeScope_Descendants, cond)
if btn != nil { defer btn.Release() }

7. Automation Patterns

UIA 的 Pattern 表示控件支持的行为。按钮通常支持 Invoke，编辑框支持 Value，复选框支持 Toggle，树节点/下拉项支持 ExpandCollapse，列表项支持 SelectionItem。

Patterngo-element 包装用途
InvokeIUIAutomationInvokePattern.Invoke()按钮点击、菜单项执行。
ValueSetValue、Get_CurrentValue编辑框读写文本。
ToggleToggle、Get_CurrentToggleState复选框/开关状态切换。
ExpandCollapseExpand、Collapse树节点、下拉框展开/折叠。
SelectionItemSelect列表/表格选中项。
if btn := tree.FindByAutomationId("equalButton"); btn != nil {
    ip, err := btn.GetInvokePattern()
    if err == nil {
        defer ip.Release()
        _ = ip.Invoke()
    }
}

8. CacheRequest 性能优化

README 把 IUIAutomationCacheRequest 作为核心改进之一。UIA 跨进程读取属性成本较高，遍历 UI 树时逐个属性读取会非常慢；CacheRequest 可以指定要缓存的属性和 Pattern，然后批量返回。

cache, _ := ppv.CreateCacheRequest()
defer cache.Release()
_ = cache.AddProperty(uia.UIA_NamePropertyId)
_ = cache.AddProperty(uia.UIA_AutomationIdPropertyId)
_ = cache.AddProperty(uia.UIA_ClassNamePropertyId)
_ = cache.AddPattern(uia.UIA_InvokePatternId)
_ = cache.Put_TreeScope(uia.TreeScope_Subtree)

rootCached, _ := ppv.ElementFromHandleBuildCache(hwnd, cache)
defer rootCached.Release()

9. 原始 UIAutomation API

如果 Element 封装不够用，可以直接操作 IUIAutomation、IUIAutomationElement、IUIAutomationElementArray、IUIAutomationTreeWalker、IUIAutomationCondition 等 COM 接口包装。

  • 创建条件：CreateTrueCondition、CreateFalseCondition、CreatePropertyCondition、CreateAndCondition、CreateOrCondition、CreateNotCondition。
  • 获取元素：GetRootElement、GetFocusedElement、ElementFromHandle、ElementFromPoint。
  • 查找：FindFirst、FindAll、FindAllBuildCache。
  • 属性：GetCurrentPropertyValue 以及大量 Get_Current.../Get_Cached... 方法。
  • 数组：IUIAutomationElementArray.Get_Length、GetElement。

10. MSAA / IAccessible

源码包含 IAccessible 与 IUIAutomationLegacyIAccessiblePattern。这对应旧的 Microsoft Active Accessibility（MSAA）接口，用于兼容老控件或从 UIA 元素桥接到旧可访问性对象。

常见 API 包括 Get_accName、Get_accValue、Get_accRole、Get_accState、AccDoDefaultAction、AccNavigate、Put_accValue 等。

如果现代 UIA Pattern 不可用，可尝试 LegacyIAccessiblePattern，但要做好控件差异和返回 VARIANT 类型复杂的准备。

11. 事件、Provider 与 TextServices

源码已定义多个事件 Handler 和 Provider/TextServices 接口，例如 AddAutomationEventHandler、AddFocusChangedEventHandler、AddPropertyChangedEventHandler、IUIAutomationPropertyChangedEventHandler、IWindowProvider、ITextProvider、ITextRangeProvider、ITextServices 等。

成熟度提醒：README 的任务列表仍写着 “UI 事件监听支持” 未完成，所以事件相关接口虽然存在，使用时要以源码和实际 Windows 测试为准。

13. 常见坑与最佳实践

必须在 Windows 桌面会话测试

服务会话、锁屏、远程桌面断开都可能影响 UIA 可见性与交互。

Release 要严格

IUIAutomation、IUIAutomationElement、Pattern、数组、Condition、CacheRequest 用完释放。

AutomationId 优先

名称会随语言变化；AutomationId 通常比 Name 稳定。没有 ID 时再用 Name/ClassName/ControlType 组合。

UI 树可能很大

浏览器/IDE 的 UI 树很深，遍历全树可能慢。优先缩小窗口范围、使用条件、启用缓存。

管理员权限/完整性级别

低权限进程可能无法自动化高权限窗口；需要同级或更高权限运行。

多语言系统

中文 Windows 中按钮名可能是“一/加/等于”，英文系统则是 “One/Plus/Equals”。示例中通常要做 fallback。

推荐工程结构：单独封装 uiahelper，提供 Init/Close、FindWindow、FindByAutomationID、Click、SetText、DumpTree 等稳定函数，业务层不要直接散落 COM 指针管理。
